현재 프로젝트의 CLAUDE.md에 표준 작업 플로우 섹션을 추가하거나 업데이트합니다.

## 모드 판별

$ARGUMENTS가 `update`이면: 기존 `## 표준 작업 플로우` 섹션을 최신 버전으로 교체합니다.
그 외(기본값): 섹션이 이미 있으면 "이미 설정되어 있습니다. 업데이트하려면 `/my-init update`를 실행하세요."라고 알리고 중단합니다.

## 0단계: 설치된 스킬 목록 수집

**커맨드 표를 이 파일에 복제해 두지 않습니다.** 실행할 때마다 실제 설치된 스킬에서 생성합니다. 손으로 관리하는 목록은 스킬이 추가·삭제될 때마다 어긋나고, 그 낡은 목록이 다른 프로젝트로 퍼집니다.

```bash
ls ~/.claude/skills/
```

각 디렉터리의 `SKILL.md` frontmatter에서 읽습니다:

| frontmatter | 표에 쓰는 값 |
|-------------|-------------|
| `name` | 커맨드 이름 → `/{name}` |
| `argument-hint` | 있으면 `/{name} {hint}` 형태로 표기 |
| `description` | 설명 열. 문장이 길면 첫 절만 쓰되 의미가 바뀌지 않게 자릅니다 |

수집 결과가 표의 유일한 근거입니다. 목록에 없는 커맨드를 표에 넣지 않고, 목록에 있는 커맨드를 빠뜨리지 않습니다.

## 순서

1. CLAUDE.md 파일이 있는지 확인
   - 없으면 사용자에게 알리고 중단 (CLAUDE.md 생성은 `/init` 커맨드로 따로 진행)

2. 0단계로 설치된 스킬 목록을 수집

3. **기본 모드**: `## 표준 작업 플로우` 섹션이 없으면 파일 맨 끝에 추가합니다.

4. **update 모드**: 아래 두 파일을 순서대로 업데이트합니다.

### CLAUDE.md 업데이트 — 표준 작업 플로우

이 표는 **파이프라인 순서**를 담으므로 순서를 자동 생성하지 않습니다. 아래 골격을 유지하되:

- 0단계 수집 결과에 **없는 커맨드의 행은 제거**합니다.
- 수집 결과에 있는데 이 골격에 없는 스킬은 파이프라인 단계인지 사용자에게 한 번 확인하고, 아니면 표 아래 한 줄로만 언급합니다.

`## 표준 작업 플로우` 섹션 전체(다음 `##` 섹션 직전까지)를 아래로 교체합니다.

```markdown

## 표준 작업 플로우

개발 작업은 아래 순서로 진행합니다. 각 커맨드는 `/my-<name>` 형식입니다.

| 단계 | 커맨드 | 설명 |
|------|--------|------|
| 0. 요구 확정 | `/my-interview [만들 것]` | 요청이 모호할 때만. 한 번에 한 질문씩 던져 대상·성공 기준·제약 확정 |
| 1. 기획 | `/my-plan [기능명]` | 가정 명시 후 설계 방향·리스크·안 할 것 정리 (plan 모드) → docs/plan/ 저장 |
| 2. 작업 분해 | `/my-split` | git branch 생성·전환 후 plan → 수직 슬라이스 단위 step 분해 (기본: step별 확인) |
| 3. 커밋 | `/my-commit` | step 완료마다 원자성 점검 후 attribution 없이 커밋 |
| — 실패 시 | `/my-debug [증상]` | 테스트·빌드 실패를 재현 → 국소화 → 근본 원인 → 재발 방지 순으로 해결 |
| 4. 완료 검사 | `/my-check` | 패키지 매니저 판별 후 타입·린트·테스트·빌드 검증, 이어서 5축 코드 리뷰 |
| 5. PR 생성 | `/my-pr [full\|auto]` | 브랜치 변경 분석 후 PR 제목 후보 + body 생성. `full`/`auto` 파라미터 시 GitHub draft PR 자동 생성 + assignee 설정 |
| 6. 리뷰 반영 | `/my-review [피드백]` | 코드 리뷰 피드백 분류 및 적용 → docs/review/ 저장 |
| 7. 개선 분해 | `/my-iterate` | 리뷰 피드백 기반 개선 작업을 step별로 분해 |
| 8. 회고 | `/my-retro` | 작업 회고 HTML 문서 생성 (피드백 이력 + 코드 변화 포함) |

진행 위치가 헷갈리면 `/my-status`로 현재 단계를 확인합니다.
```

### README.md 업데이트 — 커맨드 목록

README.md가 있고 `## 커맨드 목록` 섹션이 존재할 때만 진행합니다. 없으면 건너뜁니다.

이 표는 **전수 목록**이므로 골격 없이 0단계 결과에서 통째로 생성합니다. 정렬은 `ls` 출력 순서(알파벳)를 따릅니다.

```markdown
## 커맨드 목록

| 커맨드 | 설명 |
|--------|------|
| `/{name} {argument-hint}` | {description} |
```

행 개수는 0단계에서 센 스킬 개수와 반드시 같아야 합니다. 다르면 표를 쓰지 말고 어긋난 항목을 보고합니다.

## 완료 보고

```
업데이트: CLAUDE.md (표준 작업 플로우) / README.md (커맨드 목록)
반영된 스킬: {N}개
파이프라인 표에서 제거된 행: {목록 or 없음}
파이프라인 분류가 필요한 새 스킬: {목록 or 없음}
```
