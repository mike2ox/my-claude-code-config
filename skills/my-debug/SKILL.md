증상: $ARGUMENTS

추측으로 고치지 않습니다. 아래 순서를 건너뛰지 말고 진행합니다.

## Stop-the-Line 원칙

무언가 예상과 다르게 동작하면 **즉시 다른 작업을 멈춥니다.**

1. 진행 중이던 step 구현을 중단
2. 증거 보존 (오류 전문, 재현 절차, 관련 로그)
3. 아래 4단계 진단
4. 근본 원인 수정
5. 재발 방지 장치 추가
6. 검증 통과 후에만 원래 step 복귀

실패한 테스트나 깨진 빌드를 놔둔 채 다음 기능으로 넘어가지 않습니다. 오류는 누적됩니다.

## 1단계: 재현

실패를 안정적으로 재현합니다. 재현하지 못하면 고쳤는지 확인할 수 없습니다.

```bash
# 특정 테스트만 실행
npm test -- --grep "테스트명"

# 격리 실행 (테스트 간 오염 배제)
npm test -- --runInBand
```

**재현이 안 될 때** — 아래 축으로 원인을 좁힙니다:

| 의심 축 | 확인 방법 |
|---------|----------|
| 타이밍 의존 | 로그에 타임스탬프 추가, 인위적 지연으로 경쟁 구간 넓히기 |
| 환경 의존 | Node/브라우저 버전, 환경변수, DB 데이터 상태 비교 |
| 상태 의존 | 전역 변수·싱글턴·캐시 누수 확인, 단독 실행 vs 연속 실행 비교 |
| 진짜 랜덤 | 의심 지점에 방어적 로깅 추가 후 재발 시 재확인 |

끝내 재현되지 않으면 관찰된 조건을 기록하고 사용자에게 보고합니다. 추측으로 수정하지 않습니다.

## 2단계: 국소화

오류가 **어디서** 발생하는지 좁힙니다.

1. 스택 트레이스에서 **내 코드 최상단 프레임**부터 확인 (라이브러리 내부 아님)
2. 마지막으로 동작하던 시점 확인 — `git log`, `git diff HEAD~1`
3. 변경 범위가 넓으면 `git bisect` 또는 변경 되돌리기로 이분 탐색
4. 실패 지점 직전 입력값과 상태를 확인

의심 지점이 2곳 이상이면, 한 번에 하나씩만 검증합니다.

## 3단계: 근본 원인 파악

**증상이 아니라 원인을 고칩니다.**

각 가설에 대해 아래를 확인합니다:

- 이 가설이 맞다면, 관찰된 **모든** 증상이 설명되는가?
- 설명 안 되는 증상이 남으면 가설이 틀렸거나 원인이 2개다
- "왜?"를 3번 이상 물어 표면 아래로 내려간다

```
증상: 목록이 빈 화면으로 렌더링됨
→ 왜? data가 undefined
→ 왜? 쿼리가 error 반환
→ 왜? 변수명이 스키마와 불일치
→ 근본 원인: 타입 정의가 스키마와 동기화되지 않음  ← 여기를 고친다
```

**금지 패턴**:
- `try/catch`로 오류를 삼켜 증상만 감추기
- 원인 모른 채 `?.`·기본값으로 덮기
- 조건문 하나 추가해 특정 케이스만 우회

이런 수정이 필요해 보이면, 그건 근본 원인을 아직 못 찾았다는 신호입니다.

## 4단계: 수정 및 재발 방지

1. 근본 원인을 최소 변경으로 수정
2. **이 버그를 잡는 테스트를 먼저 추가** — 수정 전엔 실패하고 수정 후엔 통과해야 함
3. 검증 실행:
   ```bash
   npx tsc --noEmit
   npm test
   npm run build
   ```
4. 같은 원인의 다른 발생 지점이 있는지 확인 (동일 패턴 grep)

## 5단계: 복귀 안내

수정 완료 후 아래 형식으로 보고합니다:

---
**증상**: {관찰된 현상}
**근본 원인**: {실제 원인 — 파일:라인}
**수정 내용**: {변경 요약}
**재발 방지**: {추가한 테스트 or 타입 보강}
**동일 패턴 점검**: {다른 발생 지점 있음/없음}

중단했던 작업으로 복귀하려면 "이전 step 이어서 진행해줘"라고 입력하세요.
---

수정 범위가 크거나 설계 변경이 필요하면 이번 수정으로 처리하지 말고, 별도 작업으로 분리할 것을 제안합니다.

## 조사 위임 판단

증상이 모호하거나 탐색 범위가 넓으면(원인 후보가 3곳 이상, 또는 처음 보는 코드 영역) 1~2단계를 Agent tool에 위임합니다.

- description: "버그 재현 및 원인 국소화"
- prompt: 증상 + 재현 절차 + "코드 수정은 하지 말고, 재현 결과와 의심 지점 후보를 파일:라인으로 반환할 것"

수정(4단계)은 반드시 메인 루프에서 직접 실행합니다.
