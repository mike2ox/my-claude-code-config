현재 브랜치 작업에 대한 회고 문서 작성을 Agent tool로 위임합니다.

Agent tool을 호출하세요. 파라미터:
- description: "브랜치 회고 문서 생성"
- prompt: 아래 내용 전달

---
현재 브랜치의 작업 내용을 분석하여 회고 문서를 작성합니다.

아래 명령을 실행하여 정보를 수집하세요:
- git branch --show-current
- git log main..HEAD --oneline
- git log main..HEAD --format="%ai %s"
- git diff main...HEAD --stat
- git diff main...HEAD (주요 변경 파악용)
- git config user.name

---

## 0단계: plan/review 파일 통합

### docs/plan/ 통합
`docs/plan/` 디렉토리의 파일 목록을 확인합니다.

파일이 2개 이상이면:
1. 모든 plan 파일을 날짜순으로 읽습니다
2. 아래 형식으로 단일 파일 `docs/plan/{브랜치명}-merged.md`에 통합합니다:

```markdown
# [기능명] 통합 기획서

## 최종 기획 방향
(가장 최신 plan 파일의 핵심 내용 — 기능 개요, 사용자 스토리, 기술적 접근 방향)

## 기획 변경 이력
| 날짜 | 파일 | 주요 변경 |
|------|------|---------|
| {날짜} | {원본 파일명} | {초기 방향 요약} |
| {날짜} | {원본 파일명} | {변경 내용 요약} |
```

3. 원본 plan 파일들을 삭제합니다 (통합 파일 1개만 유지)

파일이 1개 이하이면 이 단계를 건너뜁니다.

### docs/review/ 통합
`docs/review/` 디렉토리의 파일 목록을 확인합니다.

파일이 2개 이상이면:
1. 모든 review 파일을 날짜순으로 읽습니다
2. 아래 형식으로 단일 파일 `docs/review/{브랜치명}-merged.md`에 통합합니다:

```markdown
# [기능명] 통합 리뷰 이력

## 리뷰 요약 테이블
| 회차 | 날짜 | 필수 수정 | 권장 개선 | 선택 제안 | 적용률 |
|------|------|---------|---------|---------|------|
| 1차 | {날짜} | {N}건 | {N}건 | {N}건 | {N}/{총}건 |

## 리뷰 상세

### 1차 리뷰 — {날짜}
(원본 review 파일 내용)

### 2차 리뷰 — {날짜}
(원본 review 파일 내용)
```

3. 원본 review 파일들을 삭제합니다 (통합 파일 1개만 유지)

파일이 1개 이하이면 이 단계를 건너뜁니다.

## 1단계: 회고 문서 작성

0단계 완료 후 아래 파일을 읽어 내용을 반영하세요:
- `docs/plan/` 디렉토리의 파일 (통합됐으면 merged 파일, 아니면 단일 파일)
- `docs/review/` 디렉토리의 파일 (통합됐으면 merged 파일, 아니면 단일 파일)

수집한 정보를 바탕으로 `docs/retro/YYYY-MM-DD-{브랜치명}.md` 파일을 생성합니다.
`docs/retro/` 디렉토리가 없으면 먼저 생성합니다.

파일 내용 형식:

# [기능명] 작업 회고

**작업 기간**: YYYY-MM-DD ~ YYYY-MM-DD
**브랜치**: {브랜치명}
**작업자**: {git config user.name}

## 기획 방향

- 이 기능을 만든 이유
- 해결하려는 문제
- 초기 설계 방향 (docs/plan 파일 기반)

## 주요 구현 내용

- 핵심 변경사항 (3-5개 항목)

## 기술적 고려사항

- 선택한 구현 방식과 이유
- 대안으로 고려했던 접근법
- 성능·접근성·유지보수 관련 결정

## 피드백 이력

docs/review/ 파일이 있으면 각 리뷰 세션을 아래 형식으로 기록합니다.
파일이 없으면 이 섹션을 생략합니다.

### 리뷰 {N} — {날짜}

**주요 피드백 요약**:
- 필수 수정: {항목}
- 권장 개선: {항목}
- 선택적 제안: {항목}

**반영 여부**: 적용 {N}건 / 미적용 {N}건

## 코드 변경 상세

git diff를 분석하여 의미 있는 변경 지점을 기록합니다.

| 파일 | 변경 전 | 변경 후 | 변경 이유 |
|------|--------|--------|---------|
| {경로} | {before 요약} | {after 요약} | {피드백 항목 or 설계 결정} |

변경으로 인한 차이 (성능, 가독성, 버그 수정 등):
- {구체적인 효과 기술}

## 배운 점 / 인사이트

- 이 작업을 통해 새로 알게 된 것
- 다음에 비슷한 작업 시 참고할 패턴
